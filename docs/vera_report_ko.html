VERA · NVIDIA NeMo Guardrails 위 윤리 계층 실험

가드레일에 윤리 하네스를 붙이면 무엇이 달라지나

NeMo Guardrails의 기본 self-check 레일 위에 원칙 기반 윤리 계층(VERA)을 붙이고, 인간 피드백과 윤리 조정이 가드레일을 어떻게 바꾸는지, 그리고 에이전트 구조 안에서 윤리 계층을 어디에 두어야 하는지 실험했습니다.

질문 1 · 하네스 효과윤리 계층을 NeMo에 어떤 방식으로 결합해야 차단·오차단이 개선되나?

구조

VERA는 NeMo 레일 안에서 Colang 플로우로 동작합니다

사용자 메시지는 NeMo의 입력 레일을 지나 LLM으로 가고, 응답은 출력 레일을 지납니다. VERA는 이 레일에 등록된 액션으로 호출되며, 원칙별 위험도를 계산해 허용 · 에스컬레이션(사람 검토) · 차단 중 하나를 결정합니다. 사람의 판정은 피드백 루프를 통해 다시 VERA로 들어갑니다.

적층(stacked) 결합

NeMo 판정→VERA 판정→둘 중 하나라도 차단 시 차단

VERA가 NeMo 뒤에 추가 필터로 붙습니다. 차단만 늘릴 수 있어서 NeMo의 과잉 거부를 고칠 수 없습니다.

중재자(arbiter) 결합

NeMo 판정→VERA가 최종 결정

VERA가 NeMo의 판정을 받아 최종 결정을 내립니다. 보호·교육 목적이 분명하거나 사람이 허용한 사례와 비슷하면 NeMo의 거부를 뒤집을 수 있습니다.

실험 E1 · 하네스 결합 방식

NeMo 단독은 윤리적 회색지대를 하나도 막지 못했습니다

유해 요청 차단률 (높을수록 좋음) 정상 요청 오차단률 (낮을수록 좋음)

평가셋: 학습에 쓰지 않은 테스트 프롬프트 34개 (유해 21 · 정상 13)

NeMo 단독은 폭탄·마약 같은 노골적 위해는 100% 막았지만, 조종·사생활 침해·차별·기만 같은 회색지대는 0%였고, "파이썬 프로세스 kill" 같은 정상 요청을 62% 거부했습니다.

적층은 차단률을 올렸지만 NeMo의 과잉 거부를 그대로 물려받았습니다. 중재자는 같은 차단률을 유지하면서 오차단을 38%에서 23%로 줄였습니다.

실험 E2 – E5 · 윤리 조정과 인간 피드백

효과를 낸 것은 다이얼 조정이 아니라 사람이 판정한 사례였습니다

피드백 학습 곡선 (F1)

중재자 적층

라벨 10개(첫 라운드)에서 대부분의 효과가 나고, 이후 라벨은 추가 개선이 없었습니다.

피드백 채널 분리 실험 (F1, 중재자)

놓친 사례는 규칙이 하나도 걸리지 않아 위험도가 0이었습니다. 0에는 어떤 가중치나 임계값도 곱해지지 않습니다.

윤리 프리셋 조정 (중재자)

엄격하게 조이면 정상 요청 오차단만 늘고, 유해 차단률은 67%에서 움직이지 않았습니다.

검토자 라벨 오류에 대한 내성 (F1)

라벨의 30%가 틀려도 피드백 없는 상태(점선, 0.74)보다 높았습니다. 5개 시드 평균.

사람의 피드백은 "판례"처럼 작동할 때 가장 강했습니다. 사람이 차단이라고 판정한 문장과 비슷한 다른 표현(패러프레이즈)을 잡아냈기 때문입니다. 반면 원칙 가중치나 차단 임계값만 바꾸는 방식은, 애초에 규칙이 감지하지 못한 사례 앞에서 효과가 없었습니다.

실시간 사람 검토(E6)는 피드백 이후에만 작동했습니다. 테스트 34개 중 5개가 사람에게 올라갔고, 모두 실제 유해 요청이어서 결과는 기본 차단과 같았습니다. 이 설정에서 사람은 정확도보다 책임성을 더해 주었습니다.

실험 E7 · 에이전트 오케스트레이션 배치

윤리 계층의 위치마다 고유한 사각지대가 있습니다

계획 수립 → 실행 → 도구 호출로 이루어진 에이전트에 12개 과제를 주고, 윤리 계층의 위치를 다섯 가지로 바꿨습니다. 아래 표는 위험 단계를 포함한 7개 과제의 결과입니다.

경계(perimeter)

대화만 봅니다. 정상적인 요청에서 위험한 단계가 생기면(데이터 유출, 감사 로그 삭제) 그대로 실행됩니다. 응답을 나중에 막아도 이미 일어난 행동은 되돌릴 수 없습니다.

감독 에이전트(supervisor)

계획 전체의 데이터 흐름을 봅니다. 하나하나는 무해한 조회가 모여 스토킹 프로파일이 되는 경우를 잡지만, 실행 중에 주입된 단계는 보지 못합니다.

도구 게이트(tool gate)

실행 직전의 모든 호출을 봅니다. 프롬프트 인젝션은 잡지만, 한 번의 호출에서 보이지 않는 단계 간 조합 위험은 놓칩니다.

다층 배치는 각 위치가 잡는 것을 합친 만큼 막았지만 검사 비용은 경계 배치의 약 3.7배였습니다. 남은 한 건(고령 고객 압박 판매)은 규칙이 감지하지 못한 표현이었고, 채팅 프롬프트로 모은 피드백은 에이전트 과제로 전이되지 않았습니다. 피드백은 도메인별로 모아야 합니다.

시사점

윤리 계층을 아키텍처에 넣을 때의 설계 원칙

  1. 추가 필터보다 중재자로 두십시오. 기존 가드레일 뒤에 쌓기만 하면 차단만 늘어납니다. 최종 결정권을 주어야 과잉 거부까지 함께 줄일 수 있습니다.

  2. 인간 피드백은 판례로 축적하십시오. 가중치·임계값 튜닝보다 사람이 판정한 사례를 기억하고 유사 사례에 적용하는 방식이 효과가 컸고, 라벨 10개 정도에서 대부분의 효과가 나왔습니다.

  3. 에이전트에서는 행동 단위로 검사하십시오. 대화 경계만 지키면 행동의 부작용을 막지 못합니다. 계획 검토와 도구 호출 검사를 함께 두고, 비용을 감안해 고위험 도구에 집중하십시오.

  4. 피드백은 사용 도메인에서 모으십시오. 채팅에서 배운 판례가 에이전트 행동으로 저절로 옮겨 가지 않았습니다.

숫자를 인용하기 전에 확인할 점

  • 파일럿 실험입니다. 데이터는 프롬프트 72개와 에이전트 과제 12개로 작고, 실험 설계자가 직접 작성했습니다.
  • NeMo 레일 런타임은 실제로 동작하지만, 그 뒤의 LLM은 시뮬레이션입니다. NeMo self-check 판정자는 의도적으로 단순한 키워드 판정기이고, 메인 모델은 모든 요청에 응하는 모델로 가정했습니다.
  • 유사도 판단은 동의어를 수작업으로 묶은 오프라인 방식이라 피드백 효과가 낙관적으로 나왔을 수 있습니다.
  • 실제 모델(engine="nim", NVIDIA_API_KEY)과 임베딩(FastEmbedEmbedder) 경로는 구현되어 있지만, 이 환경에서 모델 다운로드가 막혀 실행하지 못했습니다.
